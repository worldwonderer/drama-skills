# 通用资产图片提示词配方

## 管辖 know-how

- `IMG-01` — 先把 spec 绑定到精确的 accepted asset/variant ID，再写自然语言；
  别名或“看起来像”不算 binding。
- `IMG-02` — 识别性身份、地理、尺度和当前状态优先；质量/风格词只能精炼
  这些事实，不能替代它们。
- `IMG-07` — 将文字策略解析为结构化选择。必须可读的文字与全局 no-text
  约束不能同时激活。
- `IMG-08` — 参考图进入生成前也要通过文字政策审查；负面 no-text 不能清除
  参考图已经携带的字形、标牌、界面、水印或字幕残留。

## 1. 目的与输入

资产提示词不是剧情镜头，也不是形容词收藏。它要把已接受资产中最值得稳定的事实，变成一张便于识别、比较和后续复用的参考图意图。

开始前取得：精确 asset/variant ID，接受快照与字段指针，用途，目标构图，视觉风格，背景/光线，文字政策，创作者引用 `REF-*`，约束与排除。缺少身份决定时停在提案，不用 prompt 文案掩盖。

## 2. 从资产事实到画面语言

把事实分四篮，而不是整本 bible 照抄：

| 篮子 | 问题 | 写法 |
|---|---|---|
| 识别锚点 | 去掉服装/天气后，凭什么认出它？ | 可见形状、比例、相对位置、材质特征 |
| 状态差异 | 这次与基准版本具体差在哪？ | 有边界、可观察的 delta |
| 复用几何 | 后续镜头最怕哪里漂移？ | 方位、尺度、入口、握持面、结构关系 |
| 呈现条件 | 怎样最利于读清以上事实？ | 构图、视角、背景、光线、空场政策 |

抽象标签需要翻译成证据。例如“冷峻”本身不够；可在人物表情、站姿、服装线条或冷色环境中选择与资产事实相符的可见载体，但不得臆造伤疤、身份或剧情。

### 锚点选择启发

- **`craft_default`**：选少而正交的锚点——轮廓、比例、一个局部特征、一个材质/色彩关系通常比十个近义形容词更稳。
- **`reviewed_invariant`**：锚点必须足以让独立审查者区分该身份及所选 variant；“漂亮、奢华、高清”不能代替识别证据。
- **`craft_default`**：用相对关系表达空间，如“服务台在主入口右前方，后墙有唯一金属门”，比散列物件清单更可复用。
- **`taste_option`**：锚点可以用简洁技术文风或富有气氛的中文表达，只要不改变事实优先级。

## 3. 八段式配方

顺序是信息保真策略，不是必须出现八段标题的僵硬格式。省略不适用段，不省略类型必需事实。

1. **用途与主体**：先说是人物设定图、场景空镜、道具参考或 scoped edit，以及主体是谁。
2. **稳定锚点**：身份、地理或形制的持久事实；写可见和可比较的内容。
3. **variant delta**：只写这个 Look/View/State 相对基准的差异及当前状态。
4. **构图与尺度**：视角、画幅用途、主体占比、方向、相对位置、比例参照。
5. **材质、色彩与光线**：说明对识别有用的表面、主次色关系、光向和亮暗逻辑。
6. **背景/舞台政策**：干净背景、环境内展示或 `empty_stage`；说明是否允许人群、手或支架。
7. **文字与功能**：引用 asset source policy，再明确选择
   `readable | symbolic | blank | postproduction` render treatment，以及功能件如何可见。
8. **排除与保留**：只写当前高风险误读；edit 以 preserve 为核心。

### 可复制文体

把内部字段翻译成自然中文，避免输出：JSON 键名、hash、审查指令、重试历史、“请模型务必”、权重语法或 provider 专用 token。ID 与来源放在 Markdown 元信息，不塞进正文。正文可用分段句，但应是一段无需隐藏上下文也能理解的提示词。

### 通用骨架

```text
[参考图类型与用途]，[主体与稳定身份/地理/形制锚点]；当前为[variant 的可见差异]。
采用[构图/视角/方向/尺度与空间关系]；[材质、色彩、光向和气氛]；[背景或空场政策]。
文字政策：[政策与精确要求]。保持[必要事实]；排除[与必需事实不冲突的高风险误读]。
```

这只是填充顺序，不是答案。删掉空项和机械标签，使成品像视觉部门可直接使用的 brief。

## 4. 锚点、约束与取舍

### Identity

身份锚点必须跨临时状态成立。服装、淋湿、污渍、手持物、当下表情通常属于 Look/State，而非身份。若“银灰短发”既可能是永久特征也可能是假发，先回 assets 解决，不在提示词里擅自定性。

### Geography

场景地理用固定入口、主要区块、视觉轴和锚点之间的关系表达。镜头角度变化不自动创造新地点。提示词可选择一个 View，但不得为“好看”搬动门窗。

### Scale

尺度最好绑定同画面中的中性参照或明确尺寸关系，而非“巨大/小巧”。参照不可引入剧情角色或与 empty-stage 冲突；道具可用标尺感底座、常见手掌尺度说明或已知功能结构。

### Text policy

文字有两层，不得混成一个枚举：

1. **Asset source policy（assets owner）**：`exact_readable | graphic_only |
   no_readable_text | pending_creator_text`，回答剧情/资产真相是什么。
2. **Prompt render treatment（image-prompts owner）**：`readable | symbolic |
   blank | postproduction`，回答这次参考图怎样处理该真相。

Spec 必须保存 source policy 的 artifact/hash/field pointer、两层 mode 和映射理由。
默认映射：

| Asset source | 允许的 render treatment | 义务 |
|---|---|---|
| `exact_readable` | `readable` 或 `postproduction` | 前者逐字引用；后者保留承载区与精确文字引用 |
| `graphic_only` | `symbolic` | 保留图形存在/布局，不新造可辨字义 |
| `no_readable_text` | `blank` 或明确不可读的 `symbolic` | 不得偶然造成新名字/号码 |
| `pending_creator_text` | `postproduction` 暂存，或阻断 `readable` | 不猜文字；保留 unresolved 与下游影响 |

不按默认映射时，必须有 creator override 且不改写 source policy。

- `readable`：正文逐字引用已接受文字，并允许清晰可读；不要同时 no-text。
- `symbolic`：允许文字感图形，但明确不要求可辨字义。
- `blank`：承载面保持空白。
- `postproduction`：预留干净区域与透视/光照条件，文字后期加入。

文字不是模型可靠性承诺；它是创作和后期意图。专名、号码或 URL 若未获明确接受，不要编造。

### 参考图准入（`IMG-08`）

文字政策同时管输出意图和输入参考。绑定人物、场景、道具、关键帧或构图参考前，逐张
检查可辨文字、近似字形、号码、标牌、屏幕 UI、水印和字幕残留；不能只检查 prompt
正文有没有写“无文字”。

- `no_readable_text`：若参考仍带文字风险，先**裁切、清理、遮罩或替换**；会破坏
  身份/地理/构图时，退回资产或选择后期处理，不得靠更强的负面词假装风险消失。
- `exact_readable`：只允许批准的承载面和逐字内容；旧版本、冲突号码、其他标牌或
  字幕不能借参考图进入生成。
- `graphic_only`：允许的只是已接受的图形职责，不把偶然可辨的伪字当作合格符号。
- 生成后仍需复审成片；参考准入降低污染源，不等于承诺模型一定正确渲染文字。

**`reviewed_invariant`**：是否存在语义可辨的残留及清理是否破坏资产，需要 reviewer
看图并引用具体区域判断。已声明的 reference、text policy 和处理决定应可追溯；
**负面 no-text 不能清除**参考像素中已有的文字证据。

### Negative constraints

- **`craft_default`**：负面约束针对可预见失败，如“不要混入第二套制服”“空场，不出现演员”。
- 不用“no blur, no bad anatomy, masterpiece...”覆盖真正锚点。
- 排除项不得否定必需项，例如要求旧铜锈又排除所有磨损，要求 `readable` 又全局禁字。
- **`reviewed_invariant`**：审查排除项是否会把人物特色、场景功能或道具使用方式一并抹掉。

### 审美语言

“电影感、质感、高级、氛围感”只有在落实为构图、材质、色彩关系、光向或景深选择时才有信息量。

- **`craft_default`**：每个审美词尽量落到一个可观察选择；删掉相互替换不改变画面的近义词。
- **`craft_default`**：先建立清楚，再添加风格。参考板需要可比较性时，均匀光常优于戏剧光；但这是用途相关默认，不是硬规则。
- **`taste_option`**：写实度、媒介、颗粒、色调和镜头感由 visual style 或创作者覆盖。
- 禁止用固定词表或形容词比例做结构阻断；语义是否泛化由 reviewer 引用具体缺失事实判断。

## 5. 输出、失败征兆与检查

### 输出

- 一条有 exact source refs、recipe version/hash 的结构化规格；
- 一条清晰标注、可复制的 generic prompt；
- 必要的 warning/override，不含媒体文件或远端任务信息。

### 失败征兆

- 单看 prompt 无法分辨究竟是哪一个身份或 variant；
- 锚点被风格套话淹没；临时伤势被写进永久面貌；
- 空间只有物品清单，没有方向/关系；尺度靠“很大”；
- no-text 与 readable 同时存在；负面约束否定了主体；
- 参考图含与 text policy 冲突的标牌、界面、号码、水印或字幕，却只在正文追加 no-text；
- 文案含用户抱怨、内部字段、生成次数或“根据上图保持一致”却无目标引用。

### 检查

1. **结构**：ID、版本、类型必需字段、source refs、reference admission 决定、source
   policy → render treatment 映射和显式矛盾可确定检查。
2. **语义**：独立 reviewer 引用资产字段和 prompt 句子，判断身份/地理/尺度是否保持，不能只说“不够高级”。
3. **默认**：把泛化词提前、堆砌或重复视作可改进警告；只在必需事实缺失时才升级。
4. **选择**：风格和文体差异不单独阻断；记录创作者选择后应在重渲染中保持。
