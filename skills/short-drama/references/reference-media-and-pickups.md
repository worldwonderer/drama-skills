# 参考图、揭示时机与补拍

这份参考资料处理三个容易被混在一起的问题：参考图可以决定什么、观众此刻可以知道
什么、一个缩小范围的提示词是否仍承担母版镜头的全部内容。
方法来自对完整“剧本—资产—分镜—提示词”修改过程的定性案例阅读；示例为合成改写，
不包含私有项目内容，也不要求实际生成媒体。

## 一、先说明参考图能用来做什么

绑定一张图之前，回答四件事：

1. **它来自哪个文件、哪个版本、哪条记录**：记录准确的产物引用、`hash` 和记录 ID，而不是
   只写“参考图二”。
2. **它本次参考什么**：身份、造型/状态、地点方位、构图、尺度、效果或起始帧。
3. **哪些内容可以照着它写**：在 `may_control` 中列出本次确实要参考的可见内容。
4. **哪些内容不能跟着它一起改变**：在 `must_not_control` 中保护身份、内容、文字、状态、人数、
   道具和空间锚点等非目标事实。

`artifact_ref` 只说明绑定了哪条文本记录，不能证明智能体已经看过这条记录对应的图片。
参考绑定还要填写 `admission_status`：

- 创作者或参考图权利人提供了可以核对的画面说明时写 `creator_described`；运行环境明确
  允许检查**输入参考图**并完成检查时写 `visually_inspected`。两种情况都要填写准确的
  `reference_observation_ref`；
- 观察记录要绑定所看文件的 `hash`、检查区域、文字处理结论、检查方式和未决风险，格式见
  [reference-observation.example.jsonl](../assets/reference-observation.example.jsonl)；
- 只有 JSON 或文字描述、媒体不可见或没有授权时保持 `unverified`，不能声称像素、文字、
  水印或裁切已经通过。

检查输入参考不等于生成图片/视频，也不等于验收成片。负面提示词不能擦除参考图已经
携带的像素，构图参考也不能因为“看起来像”就用来决定角色身份。

合成示例：

```json
{"artifact_ref":{"owner":"short-drama-storyboard","artifact":"episodes/<EP>/storyboard/keyframes.jsonl","hash":"<sha256>","record_id":"KEY-X","authority":"candidate"},"role":"composition","may_control":["subject occupancy","camera side","negative space"],"must_not_control":["character identity","wardrobe","prop text","story state"],"admission_status":"unverified","reference_observation_ref":null,"unresolved_risks":["输入参考尚无可审查的文字/水印观察记录"]}
```

项目可以使用更准确的角色名，但审查者必须能看出哪些内容可以参考、哪些不能照搬。
同一张图若承担两个互不相同的作用，就拆成两条绑定记录分别审查，不写“全参考”。

## 二、说明每张参考图的具体用途

常见用途与审查问题：

| 用途代码 | 可以借用 | 默认不可借用 |
|---|---|---|
| `identity` | 稳定脸型、体态、识别标记 | 临时服装、姿势、场景、画中文字 |
| `look_state` | 已接受的造型，或伤损、湿污等状态 | 新身份、无来源道具、背景方位 |
| `geography` | 入口、区域、固定锚点、方向关系 | 图中临时人物、光线以外的故事状态 |
| `composition` | 占画比例、视线布局、镜头所在一侧、留白 | 图中人物是谁、穿什么、发生什么 |
| `scale` | 主体之间或主体与环境的相对尺度 | 风格、身份、数量、动作结果 |
| `effect` | 已接受效果的形态、范围或材质表现 | 非目标对象的消失、复制或变形 |
| `start_frame` | 本镜已接受的起始构图与可见状态 | 尚未发生的动作、终态或下一镜事实 |

“只参考构图”是有效而重要的边界：可以借用前景/背景占比和压迫关系，同时明确
不导入图中角色、服装、道具、文字与事件。尺度也优先写成可比较的空间关系、遮挡和
画面占比；具体比例只有被创作者或项目配置接受后才是约束，不能从案例
总结成通用数字。

### 多图与首尾边界

多图可以是参考绑定集合、方便人工浏览的联系表，也可以是同一运动的起止边界；三者不能
只因放在一张版面里就混成一个资产。联系表/多格板只是交付包装，每格继续保留自己的
artifact/hash、顺序、用途和文字政策，不能把固定九格当作叙事密度公式，也不能让格间顺序
替代独立镜头的起止边界。

当前套件只定义绑定 accepted shot start 的关键帧记录，**尚不提供可绑定的尾帧 artifact**。
因此视频提示词不能把任意第二张图声明为 `end_frame`，也不能从动作说明自行发明尾帧。
项目确需首尾帧交付时，先向 storyboard owner 请求扩展契约：为 end boundary 定义独立记录、
准确 boundary ref、所有权与相邻镜一致性，再由 video-prompts 只读绑定；在该契约落地前保持
未解决。动作跨度过大时先拆镜；若多张图只是不同用途，则逐张填写 `role` / `may_control` /
`must_not_control`，不猜哪张负责身份、构图、尺度或终点。

## 三、说明观众何时能知道什么

背影、腿部入画、门缝、画外声、浅景深和遮挡不只是画面风格，它们还决定观众何时
知道人物身份、看见证据或发现危险。镜头的 `audience_visibility` 要**按事实分开记录**；每条都包含：

- 准确的 `source_ref` 和一个 `fact`，防止几项揭示要求被揉成一句；
- `permission: show_now | withhold_now`；
- 当前可见/可听的 `carrier`；
- 该事实自己的 `reveal_trigger`、`protection_method` 与 `rationale`。

同一镜可以先让观众听见称呼，但仍不露正脸；另一件证据也可以留到下一个剪切点。
这些事实各有自己的揭示条件，不能共用一个含糊的“稍后揭示”。

这不是“神秘感越多越好”。若本镜承担证据揭示，遮挡证据就是失败；若剧本只允许先
看到鞋和停步位置，提前露出正脸同样是失败。审查者必须同时核对原文允许透露的信息
和本镜必须传达的内容，不能只评价构图是否漂亮。

## 四、区分母版、补拍与替代版本

同一个镜头在制作修改中可能需要：

- `master`（母版）：承担已确认镜头的全部原文要求；
- `pickup`（补拍）：只补一个动作、反应、构图或效果片段，默认与母版并存；
- `alternate`（替代版）：同一项要求的另一种实现，是否替代必须另行决定。

缩小提示词范围往往是合理的修复：把内容太多的群像、复合动作或大范围变化收成一个可控瞬间。
危险不在“变短”，而在把它悄悄当成完整母版。`coverage_scope` 因此需要：

1. 同一运动规格文件内的 `master_motion_id` 与本版本实际补充的
   `supplements_motion_ids`；
2. 逐项填写 `source_obligations`：动作、反应、对白、揭示、项目要求、结束边界都带准确的
   `source_ref`；
3. 每项要求的 `disposition` 和当前 `motion_field`，说明它由本版本承担、留在母版、
   交给另一个补拍版本，还是必须退回分镜修改；
4. `replacement_intent` 只能提出替代请求，不能在运动规格内写入审查结果或自称已经替代。

补拍版本默认 `does_not_replace_master`。若替代版请求取代母版，独立审查者核对全部要求
后，在**下游审查结论**的 `supersession_decisions` 中绑定固定的替代版和母版 `hash`
并作出决定；运动规格文件不回写该审查结论，因此不会形成文件互相引用、`hash` 无法稳定的问题。
若缩小范围的版本丢掉的信息没有其他镜头承担，就退回分镜修改；不能靠改名“特写版”
消失。

## 五、审查顺序

1. 先验证引用、`authority`、`hash` 与原文要求可以解析。
2. 再看每个参考绑定的用途、可参考内容、不可照搬内容和观察记录；没有证据则保持
   `unverified`。
3. 逐事实核对 `audience_visibility` 是否既没有提前泄露，也没有遮掉本镜必传信息。
4. 对补拍版/替代版逐项核对原文要求；替代决定只写入下游审查结论。
5. 最后才评价提示词的措辞、节奏和审美选择。

不要用引用数量、固定裁切方式、关键词清单或提示词长度代替这些判断；也不要从文字
规格声称身份、表演或特效在真实成片里已经成功。
